Install p-limit v7.2.0 for concurrency control:
```bash
pnpm add p-limit
```

Create `src/lib/executor/types.ts` with these type definitions based on RESEARCH.md patterns:

1. **ExecutionMode** - `'auto' | 'sequential'`
   - auto: parallel-safe tasks run concurrently, CLI commands run sequentially
   - sequential: all tasks run serially (exposed via --sequential flag)

2. **Task interface** with:
   - `id: string` - Unique identifier
   - `title: string` - Human-readable for progress display
   - `parallelSafe: boolean` - Whether safe to run in parallel (file ops = true, CLI = false)
   - `execute(options: { signal: AbortSignal; onProgress?: (message: string) => void }): Promise<TaskResult>`
   - `describe(): TaskDescription` - For dry-run mode

3. **TaskResult interface**:
   - `success: boolean`
   - `message: string` - Human-readable result
   - `details?: string[]` - Optional detailed info (hidden by default)
   - `noop: boolean` - True if nothing to do

4. **TaskDescription interface**:
   - `action: string` - What the task will do
   - `target: string` - Target path/command

5. **ExecutorOptions interface**:
   - `mode: ExecutionMode`
   - `concurrency: number` - Default: 4 (per RESEARCH.md)
   - `dryRun: boolean`
   - `signal?: AbortSignal`

6. **ExecutionSummary interface**:
   - `results: TaskResult[]`
   - `totalTime: number` - Milliseconds
   - `cancelled: boolean`

Export all types.

  </verify>

<task type="auto">
  <name>Task 2: Create signal handler module</name>
  <files>src/lib/executor/signals.ts</files>
  <action>
Create `src/lib/executor/signals.ts` implementing SIGINT handling per RESEARCH.md:

1. **SignalHandler interface**:
   - `signal: AbortSignal` - Signal to pass to tasks
   - `abort(): void` - Programmatic abort (for fail-fast)
   - `cleanup(): void` - Remove SIGINT listener

2. **createSignalHandler() function**:
   - Create new AbortController
   - Register SIGINT handler that:
     - Calls controller.abort()
     - Removes itself (allows second Ctrl+C to force exit per RESEARCH.md pitfall #4)
   - Return SignalHandler with signal, abort, cleanup methods

Key implementation details from RESEARCH.md:
- Use `process.off('SIGINT', handler)` after first trigger
- Do NOT call process.exit() in handler (let natural flow complete)
- cleanup() should remove listener if not yet triggered

Export: createSignalHandler, SignalHandler type
  </action>
  <verify>
- `pnpm check` passes
- `pnpm build` succeeds
  </verify>
  <done>
- signals.ts exports createSignalHandler function and SignalHandler type
- SIGINT triggers AbortController.abort()
- Handler removes itself after first trigger
  </done>
</task>

<task type="auto">
  <name>Task 3: Create progress display module</name>
  <files>src/lib/executor/progress.ts</files>
  <action>
Create `src/lib/executor/progress.ts` implementing aggregate spinner per RESEARCH.md and CONTEXT.md:

1. **ProgressDisplay class**:
   - Private: spinner (from @clack/prompts), completed count, total count, failed count

   - `start(total: number, message?: string): void`
     - Reset counters
     - Start spinner with initial message (e.g., "Cleaning up...")

   - `update(taskTitle: string, success: boolean): void`
     - Increment completed (and failed if !success)
     - Update spinner message: "Cleaning up... (3/10)"

   - `stop(totalTime: number): void`
     - If failed > 0: stop with error message "Completed with N error(s)"
     - Else: stop with "Done in Xms" (CONTEXT.md: show total time only)

   - `cancel(): void`
     - Stop spinner with "Cancelled"

Key implementation from RESEARCH.md:
- Use single spinner (not multiple)
- Use spinner.message() for updates (not start/stop cycles)
- Format time as human-readable (ms or s depending on duration)

Per CONTEXT.md decisions:
- Standard verbosity: show task names + brief status
- Summary shows total execution time only

Export: ProgressDisplay class
