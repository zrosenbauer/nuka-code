<task type="auto">
  <name>Task 1: Integrate cache cleanup into CLI nuke command</name>
  <files>src/cli.ts</files>
  <action>
Update src/cli.ts to add cache cleanup integration:

1. Add imports at top:
   - import { detect } from '#/lib/detection'
   - import { execute, createSignalHandler } from '#/lib/executor'
   - import { createCacheCleanupTasks } from '#/lib/cache'

2. Add --dry-run option to the nuke command yargs configuration:
   - type: boolean
   - description: "Show what would be cleaned without actually cleaning"
   - default: false

3. In the nuke command handler (the ["*", "it"] command), AFTER the existing nuke operations complete successfully:

   a. Detect package manager:
      const detection = await detect(process.cwd());

   b. Create cache cleanup tasks:
      const cacheTasks = createCacheCleanupTasks(detection);

   c. If cacheTasks.length > 0:
      - Create signal handler: const signalHandler = createSignalHandler();
      - Wrap execution in try/finally to ensure cleanup
      - Call execute() with:
        - tasks: cacheTasks
        - mode: 'sequential' (per CONTEXT.md: cache tasks run sequentially)
        - concurrency: 1
        - dryRun: argv.dryRun ?? false
        - signal: signalHandler.signal
      - Handle dry-run: if argv.dryRun, log what would run using clack.log.info
      - Handle execution results: log success/failure per task using clack.log.success/error
      - In finally block: signalHandler.cleanup()

   d. If cacheTasks.length === 0 and detection.primary is null:
      - Log info: "No package manager detected for cache cleanup"

4. Handle the summary from execute():
   - If summary.cancelled: clack.log.warn("Cache cleanup cancelled")
   - If any result.success === false: throw error with the failure message
   - If all results.success === true: clack.log.success for each cleaned cache

5. For dry-run mode specifically:
   - Use clack.log.step("Dry run mode - showing what would be cleaned")
   - For each task, call task.describe() and log with clack.log.info
   - Show summary: "Would execute N cache cleanup command(s)"
   - Skip actual execution

Important implementation notes per CONTEXT.md:
- No confirmation prompts (auto-run)
- Fail fast on first failure (executor handles this)
- Non-zero exit code on failure (throw error, existing handler catches it)
- Spinner text: "Cleaning {pm} cache..." per task
