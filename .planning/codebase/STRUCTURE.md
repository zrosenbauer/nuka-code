## Directory Purposes

**src/ - Source Code:**
- Purpose: All TypeScript source code
- Contains: Entry points, core logic, utilities, and library code
- Key files: `cli.ts` (entry point), `nuke.ts` (business logic), `index.ts` (public API)

**src/lib/ - Shared Libraries:**
- Purpose: Reusable utility and helper functions
- Contains: File system operations, git integration, manifest parsing, visualization
- Organized by concern: fs, git, project, tree, utils, and manifest subdirectory

**src/lib/manifest/ - Manifest Parsing:**
- Purpose: Handle reading and parsing project configuration files
- Contains: lockfile detection, package.json parsing, pnpm workspace detection
- Key files: `lockfile.ts` (detects pnpm-lock.yaml, yarn.lock, package-lock.json), `package-json.ts` (reads and parses package.json)

**dist/ - Build Output:**
- Purpose: Compiled JavaScript files (generated by tsup)
- Contains: ESM (.mjs), CommonJS (.cjs), and TypeScript declaration files (.d.ts, .d.cts)
- Generated: Do not edit manually

**scripts/ - Build & Development Scripts:**
- Purpose: Development utilities like documentation generation
- Contains: build scripts, doc generators
- Key files: `generate-docs.ts` (generates documentation)

**docs/ - Documentation:**
- Purpose: Generated and static documentation
- Contains: Architecture notes, usage guides, globs documentation
- Files: Auto-generated from scripts or manually created

## Key File Locations

**Entry Points:**
- `src/cli.ts`: CLI binary entry point (shebang: `#!/usr/bin/env node`)
- `src/index.ts`: Library entry point for programmatic use
- `dist/cli.js`: Compiled CLI binary (referenced in package.json bin field)

**Configuration:**
- `tsconfig.json`: TypeScript compiler options (path aliases: `#/*` -> `./src/*`)
- `vitest.config.ts`: Test runner configuration
- `biome.json`: Code style and linting rules
- `package.json`: Project metadata, scripts, dependencies

**Core Logic:**
- `src/nuke.ts`: All nuke functions (nukeEverything, nukeNodeModules, nukeCache, nukeBuilds)
- `src/lib/project.ts`: Project initialization, ignore file reading, root detection
- `src/lib/manifest/lockfile.ts`: Root directory detection via lockfile presence

**Testing:**
- Test files are co-located with source files using Vitest's import.meta.vitest
- Pattern: Functions contain inline tests after implementation
- Examples: `src/lib/utils.ts` (lines 27-93), `src/lib/fs.ts` (lines 19-29)

## Naming Conventions

**Files:**
- Source files: lowercase with hyphens (e.g., `package-json.ts`, `pnpm-workspace.yaml`)
- Index files: `index.ts` for barrel exports
- Tests: Inline using `import.meta.vitest` (no separate .test.ts files)

**Functions:**
- Exported API functions: camelCase, descriptive (e.g., `nukeEverything()`, `readPackageJson()`)
- Internal helpers: camelCase (e.g., `isRoot()`, `appendToGitignore()`)
- Type guards/checks: prefix with `is` or `has` (e.g., `isLockfile()`, `hasWorkspaces()`)

**Variables:**
- Constants: UPPER_SNAKE_CASE (e.g., `DIR_CACHE`, `FILE_IGNORE`, `DEFAULT_OPTIONS`)
- Let/const: camelCase (e.g., `ignoreFileCache`, `sortedPaths`, `rootDir`)
- CLI options: kebab-case in yargs definitions (e.g., `no-fun`, `verbose`)

**Types:**
- Interfaces: PascalCase (e.g., `TreeNode`, `TreeOptions`, `PackageJson`, `PnpmWorkspace`)
- Type aliases: PascalCase (e.g., type imports from type-fest)

## Where to Add New Code

**New Feature:**
- Primary code: `src/` at appropriate level (root for high-level, `lib/` for utilities)
- Tests: Inline using `if (import.meta.vitest)` block in same file
- CLI commands: Add to command definition in `src/cli.ts`

**New Component/Module:**
- Implementation: Create in `src/lib/` if utility, or `src/` if core feature
- Exports: Add to appropriate barrel file (e.g., `src/lib/manifest/index.ts`)
- TypeScript: Always include type definitions inline or in `types.ts` files

**Utilities:**
- Shared helpers: `src/lib/utils.ts` (general) or new file in `src/lib/` for specific domain
- Manifest utilities: `src/lib/manifest/` with re-export in `src/lib/manifest/index.ts`
- File operations: `src/lib/fs.ts` (existing utilities) or extend for new patterns

**CLI Commands:**
- Location: Command definition in `src/cli.ts` using yargs `.command()` API
- Handler logic: Call appropriate core functions from `src/nuke.ts` or `src/lib/project.ts`
- Pattern: Match pattern (yargs positional/option parsing) -> handler -> core logic call

## Special Directories

**dist/:
- Purpose: Compiled output from tsup build
- Generated: Yes (from `pnpm build` or `pnpm dev --watch`)
- Committed: No (.gitignore'd)
- Structure: Mirrors src/ with .js, .mjs, .cjs, and .d.ts files

**node_modules/:
- Purpose: Installed dependencies
- Generated: Yes (from pnpm install)
- Committed: No (.gitignore'd)

**.nuke/:
- Purpose: Project-specific cache directory created by initialization
- Generated: Yes (when `nuke init` runs)
- Committed: No (.gitignore'd)
- Contents: Used for internal state (currently minimal use)

**.nukeignore:**
- Purpose: User-defined ignore patterns for nuke operations
- Generated: Yes (auto-created during init with template)
- Committed: Yes (part of project, tracked in git)
- Format: Same as .gitignore (newline-separated glob patterns)
